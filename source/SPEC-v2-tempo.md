# Спецификация v2: норма дня, плавающий календарь, отложенное

> Дополнение к `SPEC-interview-prep-app.md`. Всё, что не упомянуто здесь, остаётся как в v1.
> Жёсткие ограничения раздела 1 исходной спецификации (`file://`, никаких модулей, CDN и
> сети, один самодостаточный `dist/index.html`) действуют без изменений и имеют приоритет.

---

## 0. Задача

В v1 материал сверх выбранного режима просто оставался неотмеченным в своём дне, а сам
день сгорал по календарю. При работе в режиме 20 минут это означало потерю 67% программы
без единого следа.

Нужно, чтобы:

1. День не сгорал: не закрыл — программа сдвигается, а не уезжает без вас.
2. Непройденное сверх нормы копилось в одном месте, пригодном для прогона в конце.
3. Было видно, куда вы придёте при текущем темпе.

---

## 1. Понятия

**Норма дня** — сколько блоков нужно закрыть, чтобы день считался пройденным.
Значения 20 / 60 / 120, по умолчанию **60**. Задаётся глобально в «Настройках»,
на конкретном дне может быть переопределена разово.

**День закрыт** — у дня проставлен `completedAt`. Проставляется двумя путями:

- **автоматически**, как только отмечены все пункты в пределах нормы;
- **вручную**, кнопкой «Завершить день» — досрочно, не выполнив норму.

**Отложенный пункт** — пункт из **закрытого** дня, который не отмечен как сделанный.
Сюда попадает и блок сверх нормы, и всё, что осталось при досрочном закрытии.

**Плавающий календарь** — режим, в котором экран «Сегодня» показывает первый незакрытый
день программы, а не день по календарной дате.

---

## 2. Модель состояния

```ts
type State = {
  version: 2
  startDate: string
  norm: 20 | 60 | 120        // НОВОЕ — норма дня, по умолчанию 60
  flowMode: boolean          // НОВОЕ — плавающий календарь, по умолчанию true
  items: { [itemId]: { done: boolean, conf: 'red'|'yellow'|'green'|null } }
  days:  { [dayId]:  { mode: 20|60|120 | null, completedAt: string | null } }
  settings: { theme: 'dark' | 'light' }
}
```

`days[id].mode` теперь необязателен: `null` означает «использовать глобальную норму».

### Миграция v1 → v2

Обязательна и не должна ничего стирать:

- `norm` ← 60, `flowMode` ← true;
- `items` и `days` переносятся как есть, `completedAt` сохраняется;
- неизвестные `itemId` по-прежнему игнорируются, а не роняют приложение;
- состояние v2, прочитанное старой сборкой, не должно её ломать — лишние поля игнорируются.

## 3. Поведение

### 3.1 Закрытие дня

- Как только все пункты в пределах нормы отмечены — `completedAt` проставляется сам,
  показывается сводка дня. Отдельно жать кнопку не нужно.
- Кнопка «Завершить день» остаётся для досрочного закрытия. Если норма не выполнена,
  она называется **«Завершить досрочно»** и в подтверждении сообщает, сколько пунктов
  уйдёт в «Отложено».
- «Отменить завершение» снимает `completedAt`; пункты возвращаются из «Отложено» в день.

### 3.1a Дата старта

Плановая дата старта зашита в программу (1 августа 2026) и к моменту первого запуска
обычно уже в прошлом. Стартовать с неё нельзя: пользователь получит отставание за дни,
которых не видел. Поэтому при **первом запуске** `startDate` = сегодняшний день, если
плановая дата уже прошла. В «Настройках» рядом с полем даты — кнопки «Начать сегодня»,
«Начать завтра» и «Начать с субботы — сохранить ритм».

**День недели считается от фактической даты, а не берётся из markdown.** После сдвига
старта плановый день недели из исходника перестаёт соответствовать дате, и показывать
его рядом с датой — прямая ошибка. Плановый день выводится отдельной пометкой
«(по плану Сб)», когда расходится с фактическим.

**Ритм недели.** Программа построена на ритме «Пн–Чт теория · Пт код · Сб большой блок ·
Вс behavioral», плановый старт — суббота. Старт в другой день недели смещает ритм, о чём
«Настройки» сообщают явно; кнопка «сохранить ритм» ставит ближайшую подходящую дату.

**Отставание.** Показывается, как только плановая дата дня оказалась в прошлом, —
не дожидаясь первого закрытого дня. Раньше действовала оговорка «пока не закрыт ни один
день, отставания нет»; она была нужна, когда старт по умолчанию брался из markdown и уже
находился в прошлом. Теперь старт по умолчанию — сегодняшний день, ложного отставания не
возникает, а реальное (человек не занимался три дня) обязано быть видно сразу.

Плановое количество закрытых дней считается по **полностью прошедшим** дням
(`isoDiff(startDate, today)`, без +1): в день старта отставания нет, потому что этот день
ещё идёт. Если программа ещё не должна была начаться, в прогнозе стоит «программа не начата».

**Просроченный день показывает сегодняшнюю дату.** Работа над ним идёт сегодня, поэтому
главной в шапке стоит текущая дата, а плановая уходит в справку рядом:
«Ср, 5 августа · план 2 августа · отставание 3 дня».

### 3.1b Начало программы: скрытые недели

`startWeek` (0–9, по умолчанию **1**) задаёт, с какой недели начинается программа.
Недели до неё скрыты целиком: их нет ни в «Сегодня», ни в «Программе», ни в поиске, ни в
статистике и красной зоне, и они **не занимают дат** — первый день активной недели
приходится ровно на `startDate`.

Данные при этом **не удаляются**: все 65 дней и 445 вопросов остаются в `program.json`,
отметки по скрытым дням сохраняются в состоянии. Решение обратимо в один клик, и
`verify.js` продолжает проверять полноту программы.

Значение по умолчанию — 1: Неделя 0 («Калибровка» — rapid-fire и настройка окружения)
скрыта по требованию владельца программы, который начинает сразу с Недели 1.

### 3.1c Размер дня: перенарезка

`splitSize` (0, 3, 6 или 9 верхнеуровневых пунктов; по умолчанию **6**) режет крупные дни
на части: `splitSize/3` пунктов в каждый из трёх блоков. Тема при этом не меняется — она
растягивается на несколько дней («Гонки и блокировки · часть 1 из 2»), а вся программа
сдвигается вперёд.

Порядок пунктов сохраняется: берутся все верхнеуровневые пункты дня подряд (блок 20, затем
+40, затем +60) и нарезаются группами. Подпункты не отрываются от родителя. Дни, где
пунктов не больше `splitSize`, не режутся.

**Id пунктов не меняются никогда** — отметки и оценки переживают любую перенарезку.
Id частей дня (`w1-d1p2`) при смене размера меняются, поэтому `completedAt` по ним может
устареть; чтобы это не теряло прогресс, день считается закрытым, если проставлен
`completedAt` **или** выполнена норма (`normDone`). День без пунктов («Вс 4 окт · Пауза»)
сам собой не закрывается никогда — только кнопкой.

Длительность программы при разных размерах (Недели 1–9, 518 верхнеуровневых пунктов):

```
весь день (0)   63 дня
по 9 (3+3+3)    89 дней
по 6 (2+2+2)   112 дней
по 3 (1+1+1)   192 дня
```

### 3.2 Плавающий календарь

При `flowMode = true`:

- «Сегодня» = первый день программы с `completedAt == null`;
- на карточке дня показывается плановая дата и, если она в прошлом, отставание:
  «план: 5 августа · отставание 7 дней»;
- плановые даты дней **не пересчитываются** — раздел «Программа» продолжает показывать
  исходный календарь, чтобы структура недель оставалась узнаваемой.

При `flowMode = false` — поведение v1: день определяется календарной датой.

### 3.3 Отложенное

- Пункт попадает в «Отложено» ровно тогда, когда его день закрыт, а сам он не отмечен.
- Это **витрина, а не перемещение**: пункт остаётся на своём месте в дне и виден там же.
- Отметка «сделано» доступна прямо в списке и убирает пункт из него.
- Пункт может одновременно быть в «Отложено» и в 🔴 — это разные оси: охват и уверенность.

## 4. Экраны

### 4.1 Сегодня

- Прогресс дня и полоса считаются **от нормы**, а не от выбранного режима просмотра.
- Блоки за пределами нормы приглушены и подписаны: **«сверх нормы — уйдёт в Отложено»**.
- Переключатель 20 / 60 / 120 остаётся, но меняет норму только для этого дня.
- В шапке при отставании — строка «план: 5 августа · отставание 7 дней».

### 4.2 Красная зона → две вкладки

Раздел сохраняет название и место в навигации. Внутри — два таба со своими счётчиками:

| Вкладка | Что показывает |
|---|---|
| **🔴 Не даётся** | поведение v1: пункты со статусом 🔴, опционально 🟡 |
| **⏸ Отложено** | отложенные пункты из закрытых дней |

Общее для обеих вкладок: группировка по темам, фильтр по темам, ссылка на день-источник,
кнопка «Случайные 5». На вкладке «Отложено» вместо кнопок уверенности — чекбокс «сделано».

Седьмой раздел в навигацию **не добавляется**: на ширине 360px шесть иконок в нижней
панели уже занимают всю строку.

### 4.3 Статистика — прогноз

Добавляется блок с сухими числами, без оценок и подбадриваний:

- **темп** — сколько дней программы закрывается за календарный день, по последним 14 дням;
- **финиш** — дата, в которую при этом темпе закончится программа;
- **отставание** — на сколько дней плановый график опережает фактический;
- **отложено** — сколько пунктов ждёт прогона.

Темп считается по `completedAt` закрытых дней — отдельная история отметок не требуется.
Если за последние 14 дней не закрыто ни одного дня, вместо прогноза выводится «—».

> Это сознательное отступление от §12 исходной спецификации, запрещавшей «анализ, сколько
> вам ещё учить». Внесено по прямому запросу владельца программы. Формулировки остаются
> фактическими: дата и темп, без мотивационных подсказок.

### 4.4 Настройки

Добавляются два поля:

- **Программа начинается с недели** — чипы 0…9, по умолчанию 1;
- **Сколько пунктов в одном дне** — весь день / 3 / 6 / 9, по умолчанию 6;
- **Норма дня** — 20 / 60 / 120, по умолчанию 60;
- **Не терять непройденное** — переключатель плавающего календаря, по умолчанию включён.

## 5. Опорные числа

Проверяются в `verify.js` и не должны разъезжаться:

```
норма (блоки 20 + 40)        371 пункт     64% программы
сверх нормы (блок +60)       206 пунктов   36% программы
всего                        577 пунктов
норма за день                мин 2 · медиана 6 · макс 16 · среднее 5.8
дней с нормой больше 10      6
```

Держа норму каждый день, пользователь финиширует за 64 дня — ровно в срок — и проходит
64% программы. Максимум «Отложено» при этом составит 206 пунктов.

## 6. Чего по-прежнему делать не нужно

- Переносить непройденные **пункты** в тело следующего дня: при норме 20 это даёт 386
  пунктов в одном дне к концу программы и делает экран нерабочим. Двигаются дни, а не пункты.
- Пересчитывать плановые даты в разделе «Программа».
- Добавлять мотивационные подсказки, оценки прогресса и геймификацию.
- Менять тексты программы.
